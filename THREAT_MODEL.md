# VSA website threat model

**Scope:** Production VSA website and its Supabase, Vercel and GitHub workflow boundaries. This is a public repository; never put credentials, private student data, attack instructions or actual check-in values here.

Review this document when adding a new feature or changing a trust boundary, **in the same PR**. Mark a control **unverified** unless a focused test or deployed verification proves it. Browser checks and client validation are UX, not authorization.

## Reviewer check

For each new or changed trust boundary, answer: what is the purpose; what could fail; what server-side control actually exists; which test or hosted check proves it? Record missing proof as **unverified** and link a follow-up issue. Do not call an offline mock test evidence of hosted RLS or production configuration.

For deeper security history and decisions, consult [Auth model](docs/auth-model.md), [RLS verification checklist](docs/rls-verification-checklist.md) and [failure archaeology](.claude/skills/vsa-failure-archaeology/SKILL.md). Avoid reproducing sensitive operational detail from those sources here.
